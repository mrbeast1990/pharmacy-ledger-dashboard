# Pharmacy Ledger Dashboard

Lovable: الواجهات وتجربة الاستخدام فقط

استخدم هذا القسم لتصميم الواجهات دون إنشاء منطق مالي مستقل أو قاعدة بيانات نهائية. اعرض بيانات تجريبية واضحة، مع الحفاظ على أسماء الحقول ومعانيها في القسم الثاني حتى يستطيع Codex توصيل الواجهة دون إعادة تفسيرها.



١. الإطار العام والتبديل

واجهات عربية من اليمين إلى اليسار. يظهر اسم الشركة وشعارها في موضع واضح، مع مفتاح بين دلتا الشمال ويافا. بعد التبديل تتغير الهوية والسجلات والكشوف معاً. لا يكفي تبديل الشعار مع بقاء أرقام الشركة الأخرى. استخدم مكاناً محجوزاً للشعار إلى حين استلامه، ولا تصنع شعاراً بديلاً.



٢. حسابات الصيدليات

قائمة حسابات الصيدليات التابعة للشركة المختارة، وفتح حساب صيدلية أو إضافة حساب باسمها. الحقل التجاري المؤكد حالياً هو اسم الصيدلية فقط. لا تفرض هاتفاً أو عنواناً أو بيانات لم يطلبها صاحب العمل. ربط الاسم نفسه بحساب في الشركتين لا يعني دمج رصيديهما.



٣. حساب الصيدلية / الدفتر

اسم الصيدلية، الشركة الحالية، إجمالي المفوتر، إجمالي السداد، والمتبقي. تحتها حركات الفواتير والسدادات مع مرجع كل حركة ومبلغها وأثرها على الرصيد. عرض التاريخ والرصيد المتتابع تنظيم مقترح، وليس حقولاً وافق عليها المستخدم بعد. يظهر واضحاً أن الفاتورة تزيد المطلوب من الصيدلية والسداد يخفضه.



٤. تسجيل فاتورة

نفس النموذج في الشركتين: رقم الفاتورة، الصيدلية، قيمة الفاتورة، ورفع صورة الفاتورة الأصلية أو الملف المصمم خارج التطبيق. لا أصناف ولا كميات ولا أسعار وحدات. عند الحفظ تظهر الحركة مرة واحدة في حساب الصيدلية. حقل التاريخ المقترح يحتاج تحديد هل هو تاريخ الفاتورة أم الإدخال.



٥. تفاصيل الفاتورة والمرجع

عرض رقم الفاتورة واسم الصيدلية والقيمة والمرفق المرتبط بهذا الرقم. الفاتورة تصمم خارج التطبيق بالتعاون مع صاحب العمل ثم ترفع هنا. هذه الشاشة ليست محرراً للفواتير وليست مولداً تلقائياً لها. لا تعدل قيمة الحساب بمجرد فتح المرفق أو استبداله.



٦. تسجيل سداد / جباية

اختيار الصيدلية، إدخال قيمة السداد، ورفع صورة قسيمة السداد كمرجع. السداد ينزل من حساب الصيدلية مباشرة، وليس مطلوباً ربطه بفاتورة بعينها في هذه النسخة. التاريخ حقل تنظيمي مقترح، ورقم القسيمة ليس متطلباً مؤكداً.



٧. كشف الحساب

كشف على مستوى الصيدلية، وملخص للشركة المختارة يوضح المفوتر والمجبي والمتبقي خارجاً. في يافا يظهر أيضاً حساب العمولة على الجباية وفق القاعدة قيد التأكيد. لا تضف عمولة إلى دلتا. لا تفترض إرسال الكشف تلقائياً للمدير أو وجود تصدير وطباعة قبل تأكيدهما.



٨. حالات العرض

جهز حالات فارغة قبل وجود حسابات أو حركات أو مرفقات، وحالة انتظار الحفظ أو الرفع، ورسالة فشل تحفظ المدخلات، ورسالة نجاح بعد الحفظ الفعلي. هذه حالات تنفيذ للواجهات المطلوبة، وليست وحدات عمل جديدة. لا تعرض نجاحاً وهمياً أو تغير رصيداً دائماً في نسخة العرض.
